# AGENTS.md

This file provides guidance to coding agents when working with code in this repository.

## Commands

- `npm run build` — Vite library build (ESM + CJS) plus bundled `.d.ts`/`.d.cts`. `npm start` is the same in watch mode.
- `npm run lint` — runs all `lint:*` in parallel: `lint:eslint` (ESLint, includes Prettier + JSON/Markdown linting) and the `lint:ts` group — `lint:ts:typecheck` (`tsc --noEmit`) and `lint:ts:attw` (are-the-types-wrong on a packed tarball; needs a build).
- `npm run check` — runs all `check:*` on the built output (needs a build); CI runs it in the Build job. `check:js-compat` uses es-check to require ES2018, so `src/` can't use newer built-ins such as `Array.prototype.flatMap` or `Object.fromEntries` - lint and typecheck don't catch this.
- `npm test` — single run with V8 coverage (what CI runs; CI runs `unit` and `integration` separately and uploads each as its own Codecov flag). A positional arg filters by path substring: `npm test unit`, `npm test integration`, `npx vitest run tests/unit/buildSchema.test.ts`, `npx vitest run -t "test name"`. `npm run test-watch` — Vitest in watch mode for the dev loop.

## Architecture

This is a *framework* library: it has no knowledge of any concrete syntax. Everything concrete (markdown, HTML, …) lives in downstream packages such as prosemirror-remark, which supply `Extension` subclasses. `src/index.ts` is the entire public API surface.

`ProseMirrorUnified` is a thin facade. Its constructor takes a flat list of extensions, wraps them in an `ExtensionManager`, then builds the schema, the unified processor and the two converters. Each concern is a plain `build*` function in its own file, taking the `ExtensionManager` (and the schema where needed). The editor-side parts (input rules, keymap, extension plugins, paste, node views, base keymap) are built on the first call of their method and cached in a `cached*` field of the facade - the facade is the only place that caches. Every call therefore returns the same plugin instances, so `EditorState.reconfigure` keeps their state, and apps that only parse and serialize never run those extension hooks. A build that throws leaves nothing cached, so the next call retries. `extensionPlugins()` and `nodeViews()` return copies of the cached array/object:

- `ExtensionManager` — recursively expands `extension.dependencies()` and buckets extensions into node / mark / other maps keyed by `constructor.name`, which deduplicates repeated extensions. Consequently `syntaxExtensions()` returns nodes before marks, and that ordering is what conversion iterates over.
- `buildSchema` → the single `Schema` instance shared by everything (`schema()`), built from each extension's node/mark specs (`null` name or spec means the extension contributes nothing to the schema).
- `UnistToProseMirrorConverter` (`parse`) — depth-first: find the first extension whose `unistToProseMirrorTest` matches, convert children, then call `unistNodeToProseMirrorNodes` with the already-converted children plus a mutable context object shared across the whole document. After the tree is done, every syntax extension gets `postUnistToProseMirrorHook(context)`. An unmatched node produces a `console.warn` and is dropped; a root that doesn't convert to exactly one node throws. `convertKeepingSource` (used for paste) instead keeps an unmatched node as text sliced from the source by its `position`, and returns `null` instead of throwing when that text spans lines or can't be placed (an extension returns no nodes for its parent, or it reaches the root still inline) or the root doesn't convert.
- `ProseMirrorToUnistConverter` (`serialize`) — mirror image, but only `NodeExtension`s convert nodes; marks are applied when a node's children are converted, by the matching `MarkExtension.processConvertedUnistNodes`. Neighbouring children sharing an equal mark are wrapped together; overlapping marks nest with the longest run outermost (ties: lowest schema rank outermost), and leaf marks (`unistNodeIsLeaf()`) are applied per node, innermost.
- `buildUnified` — folds `unifiedInitializationHook` over a `unified()` processor; this is where downstream extensions plug in remark/rehype.
- `buildInputRulesPlugin`, `buildKeymapPlugin`, `buildNodeViews` — collect `proseMirrorInputRules` / `proseMirrorKeymap` into ProseMirror plugins, and `proseMirrorNodeView` into the node view map. Enter isn't text input, so the input rules plugin's `handleKeyDown` passes it (unmodified, within one textblock) to the rules as `"\n"`. It does so through extra `inputRules()` instances that aren't in the editor state: first one for the `EnterInputRule`s (recognised by `isEnterInputRule` through a `Symbol.for` key, so rules from another copy of the package work too), and if none applies, one for the rest (each skipped when it would have no rules). Both run with a view whose `dispatch` moves prosemirror-inputrules' undo record to the real plugin, minus the line ending. If an `EnterInputRule` applies, Enter stops there instead of going on to the keymaps. `keymapPlugin()` has the extensions' bindings alone; only `plugins()` adds the prosemirror-commands `baseKeymap`, as a separate plugin.
- `buildExtensionPlugins` — collects `proseMirrorPlugins`, the one plugin hook on `Extension` itself rather than `SyntaxExtension`, from all extensions (nodes, marks, then others). `plugins()` returns input rules, the extensions' keymap, these, paste, then `baseKeymap` last, so that it doesn't swallow keys before the extensions' plugins see them, while extension shortcuts still win over extension plugins.
- `buildPastePlugin` — a `clipboardTextParser` plugin that parses pasted plain text with the processor and `convertKeepingSource`, keeping the marks at the cursor. Returning `null` falls back to ProseMirror's literal paste; errors are caught and logged, because throwing there would let the browser paste natively.

The unist/ProseMirror asymmetry drives the class hierarchy: unist has no marks, so `MarkExtension` maps a unist node (e.g. `strong`) to a ProseMirror *mark*, while `NodeExtension` maps to a ProseMirror *node*. Shared machinery lives in `SyntaxExtension`; `Extension` itself only carries `dependencies()`, the unified hook and `proseMirrorPlugins()`. `MarkInputRule`, `EnterInputRule` and `createProseMirrorNode` are helpers for extension authors.

The API reference is the VitePress site in `docs/` (`npm run docs:dev` to preview): `docs/guide/api.md` covers `ProseMirrorUnified`, and `docs/developing/extensions.md` covers the extension classes and helpers. Any change to a public class, method signature, or default behaviour must be reflected there. `README.md` only links to the site and shows a usage example.

## Conventions

- ESLint is strict: `typescript-eslint` strict + stylistic, `perfectionist` (natural sorting of imports, object keys, class members — expect churn if you add members out of order), `prefer-arrow-functions`, and eslint-comments requiring a description on every disable directive (`-- reason`).
- Explicit return types and `public`/`private` modifiers everywhere; type-only imports use `import type`.
- Tests: `tests/unit/` mirrors `src/` file-by-file (bar classes such as `MarkExtension` that carry only abstract members, which have nothing to test) and uses the `vi.fn`-backed extension doubles in `tests/mocks/`; `tests/integration/` builds a small real syntax (Root/Text/Paragraph/Bold/Callout extensions, plus a Link unist type deliberately left without an extension to exercise the unhandled-node path) and drives it through `ProseMirrorUnified` with `vitest-prosemirror` and a real `unified` processor - `ParserProviderExtension` supplies a stub parser and compiler through `unifiedInitializationHook`, so the tests control the unist tree without mocking `unified`. jsdom environment, `mockReset: true`, `tests/setup.ts` polyfills `Range` rects for ProseMirror.
- Tests only state `expect.assertions(n)` where assertions could otherwise be silently skipped - async tests and tests whose `expect`s sit inside a callback or a loop. This is enforced by `vitest/prefer-expect-assertions`, so let the lint decide rather than adding the count everywhere.
